## Phase 1: Discovery and Technical Scoping (£1,200, 1 to 2 weeks)

| # | Deliverable |
|---|---|
| 1 | Requirements and discovery session with the practice managers |
| 2 | Technical architecture recommendation |
| 3 | EMIS and Asteroid AI integration assessment: endpoints, authentication, permissions, patient lookup, availability, booking, cancellation, write-back, limitations |
| 4 | Detailed call-flow architecture for each journey |
| 5 | Recommended voice and AI technology stack |
| 6 | Security and NHS information governance review (UK GDPR, DPIA, DSPT, DCB0129 / DCB0160 inputs) |
| 7 | Latency and performance approach |
| 8 | MVP definition: which journeys are automated and which stay with staff |
| 9 | Development plan and effort estimate |
| 10 | Register of key technical and integration risks |

## Phase 2: Prototype and Implementation

1. **MVP build:** FAQs, new appointments and existing appointments
2. **Test suite:** synthetic patients, UK regional accents, background noise, interruptions, callers who change their request, API outages, prompt-injection attempts
3. **Pilot:** one practice, with live monitoring and daily review
4. **Rollout:** remaining practices through configuration only
5. **Handover:** dashboard, operator guide, runbooks and rollback plan

## Ways of Working

- No production credentials are requested on day one; the practice keeps control of access
- Synthetic data is used until go-live is approved
- Every action has negative tests: wrong patient, duplicate confirmation, stale slot, outage
- Weekly written progress updates
